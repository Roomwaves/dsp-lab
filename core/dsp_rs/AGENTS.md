# DSP Engine (Rust)

Real-time Rust port of `core/dsp`. Block-based, stateful, f32.
This crate is consumed by `apps/desktop/src-tauri` as a local dependency.

---

## Purpose and scope

`core/dsp` (Python) is the source of truth for mathematical correctness.
`core/dsp_rs` (Rust) is the performance-optimized real-time implementation.

**Every function here has a corresponding Python implementation in `core/dsp/`.
If the Python version doesn't exist yet, don't add it here first.**

The typical porting flow:
```
core/dsp/ (Python, batch, f64)
  → verified correct via tests
  → ported to core/dsp_rs/ (Rust, block-based, f32)
  → validated against Python test fixtures
```

## Rules

### ✅ DO
- Process audio in fixed-size blocks (`process_block(&[f32]) -> Vec<f32>`)
- Keep state in structs — never in global/static variables
- Validate inputs in `new()` constructors — return `Result<Self, DspError>`, not panic
- Use `rustfft` for FFT operations
- Load Python-generated `.npy` fixtures in tests to cross-validate results
- Expose a C-compatible FFI layer if needed by Tauri (`#[no_mangle] pub extern "C"`)
- Document every public function with `///` doc comments

### ❌ DON'T
- Allocate memory inside `process_block()` — pre-allocate in the constructor
- Panic in library code — return `Result` or `Option`
- Use `f64` for audio processing — all audio math is `f32`
- Import `tokio`, `axum`, or any async/HTTP crate — this is a pure DSP crate
- Duplicate the Python mathematical logic without first verifying it against fixtures
- Use `unwrap()` in production paths — only in tests and examples

## Block-based design (mandatory pattern)

Every filter must follow this structure:

```rust
pub struct MovingAverageFilter {
    m: usize,
    buffer: Vec<f32>,    // delay line: len = m - 1
}

impl MovingAverageFilter {
    pub fn new(m: usize) -> Result<Self, DspError> {
        if m == 0 {
            return Err(DspError::InvalidParameter("M must be >= 1".into()));
        }
        Ok(Self {
            m,
            buffer: vec![0.0; m - 1],
        })
    }

    /// Process one block. Output length equals input length.
    /// State (buffer) persists between calls.
    pub fn process_block(&mut self, input: &[f32]) -> Vec<f32> {
        // extend with history, convolve, update buffer
        ...
    }

    pub fn reset(&mut self) {
        self.buffer.iter_mut().for_each(|x| *x = 0.0);
    }
}
```

**No allocations in `process_block()`.** If the output buffer needs to be pre-allocated,
accept it as a mutable slice parameter: `process_block(&mut self, input: &[f32], output: &mut [f32])`.

## Cross-validation with Python

Python generates fixture files that Rust tests load to verify numerical equivalence:

```bash
# Generate fixtures (run from repo root after core/dsp is implemented)
uv run python scripts/generate_rust_fixtures.py
# Output: core/dsp_rs/tests/fixtures/*.npy
```

Rust test pattern:
```rust
#[test]
fn test_moving_average_matches_python() {
    let input = load_fixture("input.npy");           // float32
    let expected = load_fixture("moving_average_M8.npy");

    let mut filter = MovingAverageFilter::new(8).unwrap();
    // process in one block (matches batch Python behavior)
    let output = filter.process_block(&input);

    assert_allclose(&output, &expected, 1e-5);
}
```

Acceptable tolerance between Python (f64) and Rust (f32): **atol = 1e-5**.

## Integration with Tauri

This crate is a dependency in `apps/desktop/src-tauri/Cargo.toml`:

```toml
[dependencies]
dsp-rs = { path = "../../../core/dsp_rs" }
```

Tauri commands call into this crate — not into Python directly.
Heavy real-time processing (audio callbacks, RTA) uses Rust.
Offline analysis (coherence, system identification) uses the Python API.
